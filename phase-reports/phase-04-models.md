# Phase 4 report: models

One evolving file. Update it after every slice, and at the end of every run on this phase, even a stopped one. Never replace it with a fresh file — append and revise in place.

## 1. Summary

In progress; slices 1-5 are built and green, and all three of the phase's sections are switched and in review for the controller. The `providers` package holds one neutral call interface and three concrete adapters — Anthropic (`anthropic-sdk-go v1.75.0`), one OpenAI-compatible adapter that serves OpenRouter/DeepSeek/Ollama/LM Studio by swapping the base URL (`openai-go v1.12.0`), and a native Gemini adapter (`google.golang.org/genai v1.71.0`) — with the provider-specific thinking-mode maps in one place per family. Slice 3 adds Marshal's own agent: `daemon/internal/agents/builtin` is a read/edit/run/tools loop over that interface, implementing the same `agents.Agent` the CLI adapters do, and the catalog (`GET /v1/agents`) now genuinely lists the built-in agent last with models computed from the providers that are set up (that retired the frontend's client-side `withBuiltIn`/`BUILT_IN_AGENT` shim). Slice 4 adds the store those models come from and everything that hangs off it: the OS keychain (`internal/security/keychain.go`, `zalando/go-keyring v0.2.8`) and `marshal keys`; the `Provider` and connection wire types and their routes (`GET`/`PUT`/`DELETE /v1/providers`, `POST /v1/providers/{id}/test`, and `GET`/`PUT`/`DELETE /v1/limits/{scope}/{kind}`); the registry, the key store, and the resolver (a role's or a card's backup model, then per-provider queueing); the usage writer that also adds a call's cost to `daily_stats.cost_micros`; pricing; and cost and awake ceilings — with migration `0014_providers` adding the `usage` and `limits` tables and `0015_integrations` adding the one `integrations` table every connection shares (a provider is a row with `kind` = `provider`). Slice 5 adds the shared connection-test framework (`internal/connectiontest`) and chat titles written by the cheapest priced model, and cuts all three sections over: **S19b** (Home cost), **S26b** (Settings limits), and **S28** (Settings providers), each with its `docs/backend-checklist.md` §2.2 register row moved in the same change as `apps/web/src/data/sections.ts`. Still open: B4.3's fallback and usage **screens** (task 4.11) need a fresh design and are deliberately not built, and the phase's full gate, end-to-end specs, and budget numbers are the controller's (CI), because the owner asked for the coding only.

## 6. Rulings

- **One `Client` interface, no SDK types in the contract.** `providers.Client` covers a whole (`Complete`) and a streamed (`Stream`) call, tool use, and usage. Every type crossing it is a neutral Marshal type; no `anthropic.*`, `openai.*`, or `genai.*` type appears in the interface, so the built-in agent (slice 3) and the connection-test framework (slice 5) never import an SDK.
- **Thinking modes live in one place, per family.** `thinking.go` maps a `providers.Level` (None/Low/Medium/High/ExtraHigh) to each family's vocabulary: Anthropic a token budget, OpenAI-compatible an effort string, Gemini a `ThinkingLevel`. One map per family, not per provider id, so OpenRouter/DeepSeek/Ollama/LM Studio all share `openAIEfforts` and a new compatible provider needs no new entry. An unrecognised mode is ignored and **can never fail a call**; a provider with no mapping is sent nothing rather than a zero-value config.
- **`Config.Retries *int`.** Tests set it to 0 to disable the SDK's own retry loop, so a fake server that answers an error is answered deterministically once.
- **LM Studio row shape (decided here, per slice 2).** LM Studio is a `local: true` provider like Ollama: **no key required**, base URL default `http://127.0.0.1:1234/v1`, served by the OpenAI-compatible adapter under `LMStudioID`. Its seed row is `{ id: "lmstudio", name: "LM Studio", st: "empty", masked: "http://127.0.0.1:1234/v1", models: [], local: true }` — `masked` carries the **server URL** (the client-side `local` field already renders a URL text field, not a key field), and it starts `empty` because the daemon cannot know the server is up until a connection test runs (slice 5). Slice 4 adds this row to `apps/web/src/mock/seed/settings.ts` and the store.
- **One provider queue, retry then fallback, and the fallback is a notice.** `queue.go` holds one in-flight limit per provider, so ten parallel calls on one key do not fail on rate limits; `managed.go` retries a failed call and then moves down the chain — a role's or a card's backup model, resolved through `resolver.go`, where a model id becomes the provider and client that run it. `Service.cheapest` prefers a paid model over free local ones (so a chat title never lands on Ollama when a real model is set up), while the lenient `Cheapest` may return a free model and the strict `cheapestPriced` may not.
- **Pricing is a table, and it is the honest weak point.** `pricing.go` holds per-million read and written prices with a cache-miss upper bound; `deepseek-chat` is a cache-miss upper bound so the ordering is conservative. The numbers are written from memory and **could not be verified** (both `web_search` calls failed; section 7), so `Service.cheapest` ordering is only as good as the table.
- **Usage is one row per call, and the same cost also lands on `daily_stats`.** `usage.go` appends a `usage` row (card, project, role, provider, model, tokens, `cost_micros`) **and** adds that call's cost to `daily_stats.cost_micros`, so the Home chart and the cost detail cannot disagree. The `usage` row kept a `project_id` for that reason.
- **Limits are `(scope, kind)` ceilings in one table, and there is no `notices` table.** `limits.go` reads and writes cost-day, cost-month, and awake ceilings per scope (`global` or a project id), keyed by `(scope, kind)`; the route is `GET`/`PUT`/`DELETE /v1/limits/{scope}/{kind}`. Nothing enforces a stored limit yet — that is B5.3/B5.6 in Phase 5, and there is no `notices` table in migrations 0001-0015 (0011 is absent) to hang a cost notice on, which is why hitting a limit does not yet pause a card.
- **The secret never leaves the keychain.** `keys.go` writes the key through `security.Keychain` and stores only `keychain_ref` in `integrations`; the masked value (`sk-ant-…4f2a`) is the only form any client ever sees, produced by the daemon, never by the app. Nothing here logs a secret or writes one to a file.
- **`integrations` is one table for every connection kind, and a provider is a row with `kind` = `provider`.** `0015_integrations.sql` (`kind`, `config_json`, `keychain_ref`, `last_test_at`, `last_test_result_json`) is what later phases' GitHub/Trello/Gmail/Telegram/Discord connections will share, so `backend-inventory.md`'s `providers` row was corrected from `settings` to this table plus the keychain.
- **One wire shape for every connection test.** `protocol.TestResult`/`TestCheck`/`CheckState` serve every testable kind, so `docs/architecture.md` §18 describes one framework rather than one per integration. `OK` means "no check failed" (not "every check passed"), `Checks` is never nil (an empty list is a list), and a check that could not run is reported as such rather than omitted.
- **`last_test_at = 0` means "never tested", and the save upserts only the two test columns.** The result row is rewritten in place, so a test never clobbers a connection's config or its keychain reference.
- **A saved key is tested immediately, with no cooldown; an on-demand test respects the cooldown and refuses with `retryAfterMs`.** `connectiontest.Runner` runs a `Tester` under a five-second per-connection cooldown and a twenty-second time limit. The test right after a save skips the cooldown on purpose (the person just asked for it), and a test that cannot run for any other reason is **logged, not fatal** — a key is still saved even if its test could not be attempted. A person asking again inside the cooldown gets a **409 carrying `retryAfterMs`**, which the screen turns into the daemon's own sentence.
- **`Provider.LastTest` is what makes `invalid` reachable.** A row is `saved`/`empty`/`invalid` from its stored test result, so a refused key becomes a real state with the daemon's fix sentence rather than a client-side guess. A provider that said nothing about rate limits yields a **nil** `RateLimit`, not a zero one.
- **The connection-test runner is its own `routeNeeds` bit.** `POST /v1/providers/{id}/test` is `needsProviders | needsConnectionTests`, so the route is present exactly when the provider service is, which is what the `routes_auth_test.go` fix (section 5) made the test agree with.
- **A chat title is written by the cheapest priced model, and an empty answer falls back to the first words.** `title.go` asks the cheapest priced model and keeps the **first non-blank line**, trimmed of surrounding quotes and a trailing full stop, at most eight words and sixty characters, first letter capitalized. An empty answer is an **error** (not an empty title), so `chats` falls back to `titleFromMessage`'s first-six-words rule — a chat is always titled, and a person can still rename it (B4.7).
- **S28: the frontend uses the generated types, and the routes are `PUT`/`DELETE`.** The Settings screen reads `ProviderList`/`SaveProviderRequest` from `packages/protocol` (no hand-written mirror), which is why the client's `Method` union gained `PUT`. `ProviderRow`'s `error`/`local` are dropped when empty and re-exported through `mock/settings-types.ts`; the provider syncer publishes no topic; saving a key is the **daemon's** job even on the never-connected onboarding screen, so `commitKeys` calls `saveProviderKey` and `maskKey` is gone (the mask shape comes only from the daemon); `ProviderKeyForm` keeps the twelve-character minimum and closes only on a successful save. The **Test button** is a brief-driven addition the design does not have.
- **S26b/S19b: an absent ceiling is a real state, and 0 means "no ceiling".** `Limits` is `{ day?; month?; awake? }` where **an absent field means no ceiling is set** (moved into `data/mappers/limits.ts` and re-exported from `~/mock/types.ts`). Money crosses the wire as micro-dollars while the store keeps whole dollars (`MICROS_PER_DOLLAR = 1_000_000`). An unset ceiling shows an empty field (`NaN`) with the help text `${usage} No limit set.` in the normal tone, while a typed 0 keeps "Enter a limit above zero." in danger. Saving diffs the draft against the store and issues `PUT` for a changed value and `DELETE` for a cleared ceiling; the "Raise cost limit" confirmation stays. `costs()`'s `day`/`monthL`/`awakeL` come out `?? 0` and **0 now means "no ceiling"**, so the Home tile drops its ` of $X` clause and stays `default`, `AwakeSection` prints `N` alone and is never full, `packages/ui`'s `LineChart.limit`/`limitLabel` and `ChartLegend.limitName` are optional (no line is drawn with no ceiling), and `mock/context.ts` drops the fabricated scopes to `{ global: {} }`. `ensureProjectState` gained a third `limitsOnDaemon` parameter.
- **`Agent.Resume` for a built-in agent (the ruling the prompt requires).** `Resume` replays the persisted message history instead of handing back a session id. `agents.Agent.Resume` is written for an external program that kept its own session id (the CLI adapters' pattern), and a built-in agent has no external process at all: the conversation *is* Marshal's own data, stored as `session_events` since Phase 2. So `builtin.Agent.Resume` takes the stored history through `Config.History` and starts a fresh in-process session that already knows it, rather than passing a session id anywhere; `Capabilities().Resume` is still true, because the person really can pick the card back up. There is no second store of conversation state and nothing to reconcile: the events the adapter emits during the replay are the same events a live turn emits.
- **The built-in agent is one more `agents.Agent`, and approval is an event, not a capability.** `builtin.Adapter` implements `agents.Agent` and `agents.SettingsApplier` — no parallel interface. `Capabilities` is `Resume`/`LoadSession`/`StructuredEvents`/`ModelSwitching`/`Thinking` true and `MCP` false, and because `agents.Capabilities` has no `Approvals` field (that flag lives on the *wire* type `protocol.AgentCapabilities`), the adapter signals "I can ask the person" by emitting `PermissionRequested`, which is what the session manager and the screens already read. `protocol.AgentCapabilities.Approvals` is true for the builtin row on that basis. MCP is false because Marshal does not hand its own agent its MCP servers yet.
- **Catalog: the built-in row is the one kind Marshal cannot be without.** `Kinds()` ends with the builtin (`{Claude, Gemini, Codex, Builtin}`), which matches the design's picker order — the agents Marshal *found* first, Marshal's own after them. Its spec is `startable: true, builtIn: true`, and the `builtIn` flag is what makes detection skip it entirely: it has no program on disk, no version to test, and **no run of detection can ever mark it missing**, not even a run that times out. Its row is always `supported`, with no version and no install hint.
- **Catalog: the built-in row's models are asked for, never cached.** `catalog.Options.BuiltinModels` is a `func() []protocol.AgentModel` the caller supplies, and `List` and `Refresh` call it on **every** answer rather than caching it behind the detection TTL — so a provider key saved in Settings shows up in the picker immediately instead of after the next detection. `nil` (or an empty list) means no provider is set up yet, and that is reported honestly: an empty model list plus `noProvidersWarning ("Add a provider key in Settings to choose a model.")` on the row, rather than a broken or hidden agent.
