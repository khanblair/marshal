## 6. Rulings

**Codebase-map option (chosen by the prior session, confirmed correct on reading):** universal ctags as an external binary. Recorded in `docs/library-docs.md` §2.10 and `docs/progress-tracker.md`'s decisions log (2026-09-27), with the reasoning this run confirmed still holds: the daemon is pure Go with no cgo anywhere, and already prefers shelling out to an external process (`gitx`, agent CLIs, `internal/proc`/`internal/platform`) over linking a C library. `internal/codemap/ctags.go` implements it, with a filename-only fallback and notice when ctags is not installed.

**Lessons schema (this run's own ruling, forced by a real conflict discovered mid-implementation):** the owner's decision said to widen the existing `notes` table for lessons rather than add a parallel table. Doing that requires `notes.card_id` to be absent for a lesson (a lesson has no card). This codebase has a strict, consistent convention of never using SQL `NULL` — every optional value is a typed default (`mcp_servers.last_checked_at`'s `0`, for example) — and `sqlc`'s generated Go type for a nullable column would have changed `db.Note.CardID` from `string` to `sql.NullString` everywhere it is read, a wide ripple this run could not compile-check (checks were already disabled by the time this was fully understood). The ruling: keep `card_id NOT NULL DEFAULT ''` and **drop its foreign key** to `cards`, since a real FK cannot accept `''` for "no card" either. This broke `TestDeletingACardTakesItsMemory` (a card's note is supposed to disappear when the card is deleted, which the FK used to do for free) — caught by re-reading the test, not by running it — and was fixed by adding an explicit `cards_notes_delete` trigger that does the same thing by hand, scoped to `kind = 'card_note'`. Recorded in `progress-tracker.md`'s decisions log (2026-09-28) and in migration 0019's own header comment.

**Markdown rendering for lesson/note bodies:** not reached. No screen was built that needs one (7.13 was not started), so this decision was not made. `marked` + `dompurify` are pre-approved in `library-docs.md` §3.3 but not installed or used anywhere in `apps/web/src` today (confirmed by grep). If a future session builds 7.13, the owner's stated preference is a small dependency-free renderer for the common subset (headings, bold/italic, lists, code fences) unless a concrete need for more exceeds that.

**No `post_lesson` MCP tool:** see §8 — this is an open question, not a ruling, because forcing an answer would mean adding a tool the architecture doc's 11.4 table does not list, which `mcpserver/register.go`'s own comment says is deliberately exhaustive ("every tool the table names is registered here").
